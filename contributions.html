how we build

keep it simple

every tool follows the KISS principle - keep it simple. small tools, readable code, nothing kept "just in case". the ideas around it are the same ones we build on.

  • the smallest change that solves the problem; nothing added for later (YAGNI)
  • one place owns each fact; no repeated logic (DRY)
  • each tool does one thing well and composes (unix philosophy, rule of least power)
  • readable beats clever; less is more (worse is better)

your turn

want to help build maidware?

you don't need to be an experienced developer, and a little time is worth more here than money ever will be. these three are the ways in, and none of them is big on its own.

code

fix or add something small

each tool has its own repository and a test suite that runs offline. start with one you already use.

 translations

write a language

english is the only one here, on purpose. a hand-written set of strings beats any machine output.

 testing

run it and say what broke

a tool on your distro plus the console output beats a vague report. it gets read.

before you open anything: the full guide is CONTRIBUTING.md. the short version - run the tests, sign your commits, and know what every line does.

we don't take donations

we take help. a small tool stays alive because someone read the code and sent a fix, not because someone paid for it. if you want to keep open source going, your time is the useful thing.

help us do translations

we at maidware project need help with translations, and we want translators to help us. english is the only language here right now, on purpose. we'd rather ship none than machine-made strings that read badly to the people they're for. if you speak another language, a hand-written set of strings is welcome.

say hello, send a patch, or offer a translation: maidwareproject@proton.me

keeping open source alive is worth the effort, and it only works when people pitch in.
