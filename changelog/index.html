Maidshare

the window (maidshare-gui) 2026-10-20

- new optional Qt window around the existing CLI: a send tab (drag
in files or links, pick or force the backend, watch the CLI's
output) and a receive tab (starts the listen, shows the QR, the
token URL with a copy button, and the cert fingerprint the browser
warning shows). closing the window or pressing stop ends the server.
- no new machinery: every action is one maidshare run - the right
click menu, the terminal and the window all do the same job with one
brain. PyQt6 only for the window, everything else unchanged.
- follows the suite's Maid Scroll palette state (same six palettes,
same one-line state file as Maid Runner), so the maid windows stay
one family.
- --screenshot PATH renders the window offscreen for docs - demo
rows and a reserved-test IP only, nothing personal passes through.
- installer: copies bin/maidshare-gui + lib/maidshare-gui/, adds
the launcher entry, reports PyQt6 like the other backends, and
uninstalls cleanly (--uninstall [--purge] unchanged behaviour).

kdeconnectd early-login fix moved to Maid Helper 2026-10-20

- the version-specific patch no longer travels in this repo. Maid
Helper's kdeconnect doctor installs a user-level platform-fallback
wrapper that works across KDE Connect versions and survives package
updates: maid-helper --only kdeconnect --fix.
- no KDE Connect source patch is shipped anywhere now; Maid Helper's
wrapper is the only fix, so a future KDE Connect update cannot
collide with a stale patch.
- the installer now reports the detected Plasma, Frameworks, Qt and
KDE Connect versions, so logs show what the machine actually runs.

stronger send-side token 2026-10-17

- the http send backend's secret path now uses the same 128-bit
url-safe token as receive (secrets.token_urlsafe(16)), replacing
six random bytes (48 bits). same flow and expiry, just harder to
guess on a busy lan.

receive: uploads go straight to disk 2026-10-17

- the receive server no longer collects the request body in memory:
multipart parts are written to their final file as they arrive in
bounded chunks, so a huge upload costs kilobytes of RAM, not
gigabytes. the declared size is checked against free disk space
first, a new MAID_MAX_FILE_MB cap bounds each single file
(default: the request cap), and a rejected or broken upload leaves
no partial file behind.

receive resource bounds 2026-10-15

- uploads stream in 64 KiB chunks straight to disk (RAM stays flat), capped at
MAID_MAX_MB (default keeps the old 500), at most 4 concurrent
uploads (rest get 503), 60 s per-connection socket timeout, and
the server still auto-expires. plaintext answers nothing.

encrypted browser directions (https + TOFU) 2026-10-15

- send (http backend) and receive now serve https only, with a
throwaway per-run cert (openssl, 1-day validity, deleted after).
the terminal prints the sha256 fingerprint - compare it with the
browser's certificate warning before proceeding (trust on first
use). token gate + auto-expiry still apply on top.
- plaintext answers nothing on those ports anymore (tested).
- needs the openssl CLI now; without it the http backend stays off
with a plain error instead of falling back to http.

dispatcher fix 2026-10-15

- parallel sends no longer join backend and filename with |; filenames
containing a literal pipe now send to the right backend intact.

receive hardening + concurrency 2026-10-14

- uploads save atomically (O_EXCL, concurrent same-name uploads can't
clobber), hostile filenames get basename-stripped, control chars
stripped from logs, oversize rejected by header before reading a byte,
planted symlinks dodged, tracebacks never leak.
- http send dir is token-gated like receive (no open listing).
- multi-file sends run concurrently (one job each); http files share one
server since the port is fixed for firewall sanity.
- firewall hint suggests runtime-only rules and runs backgrounded so a
slow firewalld never blocks a send.
- tests/: full localhost suite (serve, upload, traversal, symlink plant,
dupes, size cap) + CI. installer downloads nothing.

Maid AU

maid au gui: updates in a window 2026-10-20

check first, real update after, streaming output, summary panel and a
shareable report. ships as the "Maid AU" launcher (maid-au-gui); the
terminal flow is unchanged.
- the window honors the same screenshot-friendly flags and never
reboots for you.

kdeconnectd early-login fix moved to Maid Helper 2026-10-20

- the version-specific patch no longer travels in this repo. Maid
Helper's kdeconnect doctor installs a user-level platform-fallback

controller kmps follow the running kernel 2026-10-18

- the openSUSE controller stack no longer assumes the -default
kernel: it takes the flavor from the running kernel's release suffix
(uname -r ending in -longterm -> longterm, the same convention the
kmp names use) and installs the xone/xpadneo/hid-tmff2 kmps built
for it, so a longterm (or other) kernel gets its own builds.
- a flavor the repos publish no build for is skipped with a plain line
in the log; the rest of the controller stack still installs.
- the controller health check and the updater's count of missing kmps
resolve the same flavor, so both speak about the packages the
machine really needs.

maid suite finds and clones from github 2026-10-17

- the maid suite no longer guesses by folder name: each family repo is
matched by its github origin (so a checkout anywhere counts, e.g.
Maid Helper under MHE/), and one that is not on disk yet is cloned
from its github url into ~/.local/share/maid-au/suite.
- the status line reads "maid suite: enabled - pulling from github Maid
BT, Maidshare, Maid Watcher, Maid Helper, Maid Runner". Maid Watcher
has no repo of its own - it ships inside Maid BT - so pulling Maid BT
covers it.
- tests point the suite at a local fixture origin (MAID_SUITE_LIST) so
the suite is exercised with no network; a new test covers the clone.

snapshot honesty + maid suite visibility 2026-10-17

- a failed pre-update snapshot is now said loudly (console + log) on
pacman, dnf and apt instead of continuing silently, and zypper got
the strict --require-snapshot check the others already had: no
snapshot before the upgrade now aborts when the flag is set, and
says so loudly when it is not.
- maid suite pulls list the incoming commits and changed files in the
log, and UPDATE_MAID_DEPLOY=1 states it is rerunning installers on
exactly those commits.

controllers via helper off-suse 2026-10-15

- non-openSUSE distros drive Maid Helper's gamepad doctor when it is
installed (same UPDATE_CONTROLLERS=1 opt-in, same logging); without
Helper the old guidance stands.

appimage integrity 2026-10-15

- direct links (Name|URL) fetch https-only now (plaintext refused,
redirects can't downgrade via --proto '=https'); optional third
field pins the expected SHA-256 (Name|URL|SHA256), verified before
anything is replaced - mismatch or malformed pin leaves the old
file alone and marks the run partial.

installer + updater fixes 2026-10-15

- backups only on real change: the compare now runs against the
rewritten file content, so reinstalls no longer pile up
.bak-<timestamp> copies of the desktop file.
- install and --uninstall both honor --prefix/DESTDIR (program
files use the same BINDIR/SHAREDIR either way).
- controller zypper log uses mktemp instead of a fixed /tmp path.
- --require-snapshot flag parsing keeps arguments intact (array,
no word-splitting rebuild).

maid suite awareness 2026-10-14

- the updater knows its own family (Maid BT, Maidshare, watcher,
Maid Helper, Maid Runner): --check reports behind checkouts,
full runs pull --ff-only, diverged trees are left alone and flagged.
UPDATE_MAID_DEPLOY=1 also reruns each installer; default only pulls
code and tells you to deploy. MAID_SUITE=0 opts out entirely.

appimages 2026-10-14

- ~/AppImages / ~/Applications *.AppImage files update through
embedded info when appimageupdatetool exists, plus user direct links
(~/.config/maidau-appimages.conf, Name|URL per line) that only
download on change (etag cache) with backup-before-replace. failures
mark the run partial, never failed.

controllers are opt-in 2026-10-14

- Bazzite KMP stack only runs with UPDATE_CONTROLLERS=1. don't want
it? just never opt in.

faster runs: stop re-downloading metadata 2026-10-14

- zypper backend refreshes once; later installs in the same run pass
--no-refresh (grub plugin ensure, controller installs via
ZYPPER_NO_REFRESH). was 3-4 metadata downloads per run.
- fwupd skips its refresh when metadata is fresher than 24h
(override: FWUPD_CACHE). still always checks for actual updates.
- what still takes time is downloads + installs themselves - that part
is the distro's work, no script can skip it.

snapshot honesty + failure policy 2026-10-14

- snapshots are best-effort by default and say so; --require-snapshot
aborts the upgrade when no snapshot tooling works.
- new PARTIAL state: failed AUR builds (opt-in via UPDATE_AUR=1, was
always-on before) report partial instead of hiding.
- reboot hints use authoritative signals where they exist
(/var/run/reboot-required on apt, needs-restarting -r on dnf,
staged kernel vs boot time on pacman), name patterns only as backup.
- zypper dup documents why --allow-vendor-change is there.
- sudoers guidance rewritten: risk stated plainly, validate-then-install
flow (visudo -c -f first, mode 0440).
- arch installs with full -Syu (partial upgrades unsupported).
- log keeps 1000 lines; controllers wording fixed (health check never
fails the run, failed updates do).
- tests/: fixture-driven suite covers all four backends, strict abort,
partial state (11 checks, runs in CI).

Maid BT

Maid BT v1.1 (this release) 2026-10-21

- dock-aware goes: earbuds inside their charging case go silent (closed
case powers them off). maid-watcher probes instead of retrying blindly,
buds-fallback stands down after repeated silent connects, and any
reconnect re-arms. no more retry storms while the buds are parked.
- smart fallback: "when the buds dock, hand audio to the output used
before them" (GUI checkbox; falls back to the configured fallback
speakers when that output is gone). music keeps playing through the
move now - the pause/resume cycle covers the dock transition, so
Chromium/Electron apps no longer stall.
- soundcore device control (Liberty 5 family): battery + ANC mode +
10-band EQ written into the buds' own memory from Maid BT. The wire
protocol facts come from the GPL OpenSCQ30 project; Maid BT speaks it
through our own clean-room Python implementation (MIT) - credit and
details in the About page and README.
- new settings window: gear opens "Maid BT Settings" with exactly the
Maidware pages (Earbuds / Behavior / Equalizer / About) - no Plasma
stock "Keyboard Shortcuts" page. Plasma's own dialog still exists in
the right-click menu and now includes the Equalizer page too.
- model database: full Soundcore family (Q/Life/Space/headphone series
with device codes), multipoint/codec/case/home-ecosystem quirks for
~40 brands; maid-watcher model "NAME" CLI; docs/DEVICE-SUPPORT.md
(generated) lists what is natively supported on Linux.
- phone switching from KDE Connect: the paired device's "run command"
list gets three bluetooth commands ("Earbuds: audio on PC", "Earbuds:
audio on phone", "Earbuds: who has audio") backed by bin/maid-switch
(pc|phone|status), calling the same release/on machinery as the
applet. existing personal commands in that list are preserved and
Maid BT config snapshots live in ~/.config/kdeconnect-cmd-backup-*.
- soundcore device control is live end-to-end: real reads (battery/
firmware/dual connection) and writes (ANC modes, NC strength, preset
and custom EQ curves) verified against a Liberty 5 on the wire; the
settings window shows the curve that is actually on the buds and a
failed read says so honestly instead of showing stale zeros.
- model database lookup understands short aliases ("Liberty 5"
resolves to "soundcore Liberty 5") - the EQ page no longer shows
"not supported" for buds whose configured name is the short form.
- bluetooth stability: WirePlumber quality/A2DP-only guards deployed
with the service, reconnect back-off refinements, battery monitor
and call watcher cleanups. Toggle actions now survive missing rfkill
in the systemd user PATH.
- default codec ladder drops LDAC (wireplumber/52-bt-max-quality.conf
= [aac sbc_xq sbc]): adapters with the Realtek LDAC stall lose
packets until quality collapses, so AAC and SBC-XQ are offered
instead. the max-quality pin stays an explicit opt-in (helper GUI).
- a2dp watchdog in buds-fallback: while buds are connected, a dead
transport is re-asserted every ~12 ticks instead of leaving the card
stuck at profile "off" with silence until a manual profile flip.
- settings window fixes: pages hosted in Maid BT's own window render
correctly again (the switch handler destroyed each freshly-loaded
page via sourceComponent's last-set-wins rule), page roots use
host-agnostic ScrollablePage, the EQ strength slider applies on
release, and the About pane no longer logs undefined-assignment
errors.
- maid-setup notes the model database quirks (multipoint/LDAC hints)
into the generated config.

gui wording 2026-10-21

- the applet describes itself with its gui parts now: "A Linux-only
Bluetooth earbuds switcher - tray applet + helper window".
same wording on the repo description. nothing in behavior changed.

### settings pages

instead of only Keyboard Shortcuts and About. Earbuds covers MAC,

fallback sink honesty 2026-10-18

- the fallback sink is stored as a name, never a pulse index: indexes
are assigned per session and go stale, which used to make the park
fail silently (audio just stopped). the daemon now warns at start
when the config holds a bare number, checks the sink is really there
before parking, and logs it when it can't. the installer resolves a
typed index to the current name instead of writing it down.
- the systemd units carve out ~/MaidLogs for the audit trail: it was
silently dead inside their read-only sandbox (daemon and notification
menu both).

intent listener audit 2026-10-15

- full auth review of the port 8899 listener: token required on every
endpoint (header preferred, query legacy), constant-time compare,
fail-closed with no token file, fixed action allowlist, no shell,
no query in logs, sandboxed unit. added a 60 s per-connection
socket cap and a MAID_INTENT_PORT override so the suite tests
auth live (bad token 403, both token paths, unknown 404, no leaks).
- installer only mints the token when missing, so a running daemon
never goes stale.

dual-connection buds 2026-10-15

- opt-in MULTIPOINT=1 in bluetooth-buds.conf: release (and the
phone intents behind it) parks the PC for 8h instead of 20 min, so
dual-link buds share phone+PC all day without the daemon fighting
the phone. explicit on cancels anytime. single-link behavior
unchanged. (Bluetooth can't see the phone-side link, so this is a
tell-it-once flag, not auto-detection.)

max-quality audio 2026-10-15

- opt-in 52-bt-max-quality.conf (installer offers it): pins the A2DP
codec ladder LDAC > AAC > SBC-XQ > SBC and unlocks high-bitpool
SBC-XQ, so fallbacks land closer to LDAC than stock SBC.
- opt-in QUALITY_LOCK=1 in bluetooth-buds.conf: the switcher and
the fallback daemon pin LDAC (a2dp-sink) after every switch and
restore it on mid-session downgrades. never touches HSP/HFP calls.
- the lock also rescues HSP stuck states with a free mic (post-restart
silence): switches to LDAC only when no app captures the BT mic.
- fixed: BATTERY_BOOST=1 from the conf is honored again (the default
assignment used to clobber it, so the opt-in never took effect).

installer fixes 2026-10-15

- backups only on real change: the compare now runs against the
rewritten file content, so reinstalls no longer pile up
.bak-<timestamp> copies of every desktop file.
- --uninstall honors --prefix/DESTDIR: program files come out of
the same BINDIR/SHAREDIR/SYSDDIR the install used.
- shipped example config is placeholder-only again (Buds 1, no real
product names); the personal-data test is now case-insensitive so
variants can't slip through.

needs KDE Connect to know the phone is gone; never grabs blindly.

audio delay tuning 2026-10-14

- new opt-in wireplumber/51-bt-no-suspend.conf: kills the ~1s

- maid-watcher status now shows the live A2DP profile (codec) so
lip-sync lag can be matched to a player-side A/V offset.
- profile enforcement retries twice on slow card appearance, shrinking
the switch gap.

yours - no manual switching. yours connect first, other paired

hands-off off). yours still win when they show up, hands-off silences
all of it, yanked devices park on fallback, and the buds timer pauses

- switches now pause Playing chromium/electron apps over MPRIS and

intent + installer hardening 2026-10-14

- intent server never logs query strings anymore, so a ?token= can
never land in the journal. new preferred auth: X-Token header
(query still works for old macros).
- installer no longer enables bt-intent by default - opt-in prompt,
off for non-interactive runs. core switching never touches network.
- token file created with umask 077 (never 644, even briefly); warns
instead of silently failing without python3.
- kdeconnect moved to optional (best-effort, tolerated if missing).

- sed home rewrite survives & in $HOME.

- intent server no longer logs query strings, so a legacy ?token=
can never land in the journal. new preferred auth: X-Token header

battery boost (buds-fallback.sh) 2026-10-14

- watcher reads earbuds battery over BlueZ (Battery Percentage) and
matches the A2DP codec to it: 75%+ LDAC, 45%+ AAC, 15%+ SBC-XQ,
below that SBC. check every 60s, at most one switch per 3 min,
never touches the profile mid-call (HSP/HFP left alone).
- off by default (BATTERY_BOOST=0). turning it on means transport
teardowns on purpose, and on some plasmashell builds any A2DP
teardown segfaults the audio thread (spa.bluez5: Failure ... →
QAudioContext SIGSEGV - seen live here). flip it to 1 only if your
desktop survives a manual profile switch:
pactl set-card-profile bluez_card.<AA_BB_CC_DD_EE_FF> a2dp-sink-aac
then back, with no crash. if it crashes, leave it 0 - warm link +
no teardowns is the whole crash strategy of this package.

root, no package rebuild, survives KDE Connect updates; takes effect
at the next login.
- no KDE Connect source patch is shipped at all: the wrapper is the
only fix, so a future KDE Connect update cannot conflict with a stale
patch. the old RPM-style duplicate and the per-repo copies are gone.
- Android remote filesystem: the wrapper puts a small sshfs shim on
the daemon's PATH. Android 11+ denies listing /, so KDE Connect's
sshfs ...:/ failed with "sshfs finished with exit code 1" while
/storage/emulated/0 was readable. the shim rewrites only the bare
root, leaving a path the phone already supplied alone; "Browse this
device" now opens shared storage.
- the sibling installers no longer carry their own copies of the patch:
one suite fix, one place. maid-helper --only kdeconnect --fix is the
documented path (Maid BT, Maidshare, Maid AU, Maid Runner, Watcher
changelogs point here).
- every installer now reports the detected Plasma, Frameworks, Qt and
KDE Connect versions; Maid BT skips its plasmoid on Plasma older than
6. the doctor prints the same line, so a bug report starts with the
stack that produced it.
- install-suite.sh now includes Maid Runner, so the meta-installer
covers all five tools; Runner accepts --no-packages for quiet runs.

fixes: an honest codecs check, a window you can read 2026-10-18

- codecs: the check asked ffmpeg's decoder list for libmp3lame - an
encoder only - so healthy systems were told "NEEDS FIX - videos/music
may not play". it now checks the decoders that matter (mp3/aac/h264),
and the stub farm fakes real ffmpeg output so the old bug can't hide
behind the test again.
- launcher: the terminal window no longer vanishes the moment the report
ends - it waits for enter, and when the check found trouble it offers
to apply the safe fixes right there (sudo asks inside). a desktop
default terminal that is no longer installed now falls back instead of
failing silently.
- dispatcher: the run log the readme and uninstaller promise
(~/.local/share/maid-helper.log) is finally written - run header,
every module's output, result line.
- print: "no system default destination" is said in words instead of
leaking raw lpstat output; the Maidshare backend list loses its stray
trailing space.
